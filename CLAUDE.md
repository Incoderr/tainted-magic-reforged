# Tainted Magic: Reforged

Port of Tainted Magic 8.2.0 (MC 1.7.10, John Yorke) as an addon to Thaumcraft 4: Reforged (`../thaumcraft-4-reforged`, "the base" below) for Minecraft 26.3 on NeoForge. Logic, numbers, recipes, texts and assets of the original are carried over 1:1, the technical side is written on modern APIs.

This file describes how to develop and port the mod. Phase status, test counts, run dates and log paths do not belong here. Add a line only if an agent would make a mistake without it: a non-obvious API rule, a required order of steps, or a deliberate deviation from TM that would otherwise get "fixed" back.

## Principles

- Source of truth for behavior: the TM sources in `reference/tm-src` (yorkeJohn/Tainted-Magic, commit `e7f1640d` pinned in `tools/fetch_tm.py`: tag 8.2.0 plus translation updates). TM code is read as data, nothing from it is executed. The deobf Thaumcraft and Baubles jars in `reference/tm-src/libs` are not used; the decompiled TC4 lives in the base `reference`.
- Integrations with other mods are excluded, except JEI and REI.
- TM bugs are fixed only if they break the game (dupes, item loss, NPE, desync, server crash). Gameplay quirks stay.
- The server validates what TM trusted from the client. Client classes never leak to the server, everything must work on a dedicated server.
- Resources are made by Python generators in `tools/`, datagen is not used.
- The original is CC BY-NC-ND 4.0, which forbids sharing adaptations. The port is `All Rights Reserved` for personal use and is not redistributed.
- TM focus upgrade ids (`SANITY_UPGRADE_ID` 64 .. `DIFFUSION_UPGRADE_ID` 68) are constants, not config keys: the base `FocusUpgradeType` takes the number in its constructor during mod construction, before a SYNCED config is loaded. Their lang keys are the base `focus.upgrade.<name>.name`/`.text`.

## Environment

- Mod `taintedmagic`, package `taintedmagic`, asset namespace `taintedmagic`, archive `tainted-magic-reforged`, version 1.0.
- MC, NeoForge, ModDevGradle, JEI, REI, TerraBlender and Java versions match the base and `../witching-gadgets-reforged` (`gradle.properties`).
- The base is included as a composite build (`settings.gradle`), dependency `implementation "thaumcraft:thaumcraft-4-reforged:1.0"`. The base repository must sit next to this one. The base is not edited from the addon.
- `neoforge.mods.toml`: the `thaumcraft` dependency is required with `ordering="AFTER"`, so the addon constructor runs after the base constructor. Research and recipes are registered from the addon constructor.
- `runGameTestServer` runs with `--tests taintedmagic:*`. The test structures `taintedmagic:test/platform` (7x7x7 stone floor) and `taintedmagic:test/tall` (11x20x11, for trees) are generated by `tools/gen_testing.py`. GameTest closes every structure with a barrier ceiling at its top, so anything that grows above 7 blocks needs `TmGameTestSuite.structure("test/tall")`.
- `run/` needs `eula.txt` with `eula=true` (gitignored).

## Architecture

- Same layout as WG: `platform/` and `client/platform/` for diverging version APIs, `registry/` (`ModItems`, `ModBlocks` with `withItem`, `ModCreativeTabs`), client entry point `client/TaintedMagicClient`. `tools/check_seams.py` fails on forbidden imports outside the seams and on client class imports outside `client/`.
- TM `ConfigHandler` keys keep their names and defaults but are split by when they are read: `Config` (SYNCED) holds gameplay values, `StartupConfig` (STARTUP, loaded during registration) holds `CUSTOM_RESEARCH_TAB_BACK` because the base fixes a category background at `registerCategory`, `client/TmClientConfig` holds the display-only `RESEARCH_TAGS`.
- The creative tab is TM `TMCreativeTab`: the icon is a shadow metal capped warpwood wand, the tab starts with a full warpwood staff, wand and sceptre (shadow metal caps), then every addon item.
- A feature lives in `taintedmagic/<feature>/` and exposes one `<Feature>Feature` class with `load()`, `research()`, `recipes()` and `aspects(AspectRegistry)` when needed, plus one line in `Features.java` (and `client/ClientFeatures.java`, `tools/features.txt` when they exist; these use `merge=union`).
- GameTests live in `test/<Feature>GameTests.java` on `TmGameTestSuite`, registered with one line in `Features.tests`.
- Research category `TAINTEDMAGIC` like TM `ResearchRegistry.CATEGORY_TM`.

## Research and recipes

- TM registered all research in one `ResearchRegistry` and all recipes in one `RecipeRegistry`; the port keeps that shape: `research/TmResearchTree` and `crafting/TmRecipeBook` (written once from the tables by a conversion script, maintained by hand since), registered from the constructor after `TmResearch.init()`. Recipe keys are the TM `recipes` map keys verbatim (`ItemMaterial:0`, `ItemKatana:inscription1`); base recipe keys are plain strings, colons are fine.
- `tools/extract_tm.py` interprets `RecipeRegistry` and `ResearchRegistry` with `tools/tmjava.py` (the WG/TT Java expression parser) into `tools/tm_recipes.json` and `tools/tm_research.json`. Items resolve through `id_map.json` (TM items), `tc4_refs.json` (`ConfigItems`/`ConfigBlocks` metas, `Items`/`Blocks`); a TC4 entry "replaced by vanilla X" becomes X (`itemNugget:0` is `minecraft:iron_nugget`), a bare `Item` in an arcane recipe is meta 0 like TC4, a wildcard meta becomes an `anyOf` in meta order. Do not edit the tables by hand; rerun the extractor.
- GameTests `research_table_*` compare every registered research (position, clamped complexity, flags, parents, triggers, aspects, warp, pages) and every recipe (type, research, result with data, instability, aspects, every ingredient slot) with the tables, check that all parents exist and that every page recipe resolves.
- `TmResearch.item(key, aspects, column, row, icon, complexity, warp)` keeps the TM argument order (icon before complexity). Text pages without a dot become `tc.research_page.<key>.<page>`. `TmResearchItem` adds `INFUSION` to the hidden parents when a page is an infusion (TM `resolveInfusionParent`); explicit lists keep their order. With `RESEARCH_TAGS` the research text key is `taintedmagic.research_tag.<key>`, which `convert_assets.py` writes as `[TM] ` + the `tm.tag` text (the client sets `TmResearch.setTags`).
- `TMELDRITCHMAJOR` (TM `ThaumcraftResearchItem`, from Thaumic Exploration) is `TmLinkedResearchItem`: stub, hidden, complexity 1, a sibling of the base `ELDRITCHMAJOR`, name, text and pages from it, secondary when the original is.
- Infusion recipes whose TM output was an NBT tag (`goggles`, `mask`, `inscription`) are `TcStack.withData(central, ...)`: the base infusion copies the central item and stores the pair in `InfusionKeys.TAGS`, like its own fortress helmet upgrades. Features read those tags from there.
- Shaped crafting recipes with a TM key (the shadow metal tools) are vanilla JSON from `gen_recipes.py` plus a `CraftingRecipeRef` for the research page; the keyless TM recipes (ingot/nuggets, planks) live in the feature generators.
- Items of later phases are registered as plain placeholders under their final ids (`wands/`, `foci/`, `armor/`, `tools/`) so every research page and recipe resolves; each phase replaces the placeholder class without changing the id. The katanas have no flat texture in TM and get their model with the katana.

## Content notes

- Rarity "Creation" (TM `EnumHelper.addRarity`, gold) is the extended enum constant `TAINTEDMAGIC_CREATION` from `META-INF/enumextensions.json` (`registry/TmRarity`, declared by `enumExtensions` in `neoforge.mods.toml`). Item rarities follow TM `getRarity` per meta.
- Client effects of common code go through `fx/TmFx`, set by `client/ClientFeatures` to `client/fx/TmClientFx` (base `SparkleFx`/`WispFx` on `WorldFxRenderer`).
- Materials (`materials/`): the 12 `ItemMaterial` metas are plain items; the bloods return the base `glass_phial` (TM `setContainerItem(itemEssence)`). Salis works as a dropped item in the overworld only: at age 100 the server toggles the weather like TM `toggleWeather` (through `WeatherData`) or moves the dimension's default world clock to the next 14000 or 24000 (TM `skipToDayOrNight`); sounds are played by the server for everyone. The void blood armour recipe arrives with the armour.
- Warpwood (`warpwood/`): TM log meta 2 (the knot, hardness 25, 1-5 base `void_seed`, wisps and `craftfail` when broken) is the block `warpwood_knot` without an item, like the base `silverwood_knot`. Logs, knot, planks, leaves and sapling are not flammable (TM flammability 0). Leaves use vanilla `LeavesBlock` decay like the base silverwood leaves (TM decayed only beyond 4 blocks; vanilla uses 6), drop nothing on decay and drop themselves only to shears or silk touch, and do not dampen light. The sapling is the 1.7 `BlockSapling` (two stages, 1 in 7 per random tick at light 9, bone meal 45 %); `WarpwoodTreeGenerator` is TM `WorldGenWarpwoodTree` (knot instead of the TC4 silverwood node knot, nightshade bushes on grass or sand around it every time the tree grows). The fertilizer only converts a base silverwood sapling.
- Wands (`wands/`): the warpwood rod (250, cost 16, glowing) and staff (`warpwood_staff`, 500, cost 20, glowing, runes) and the four caps (shadowmetal 0.65/12, cloth 0.97/2, crimsoncloth 0.93/3, shadowcloth 0.93/4, no special aspects) go through `WandRegistry.registerRod`/`registerCap` with the TM tags, so the base research keys `ROD_*`/`CAP_*`, the base wand recipes and the `item.Wand.<tag>.cap`/`item.Wand.warpwood.rod` names line up; the model textures are the TM `textures/models/ModelWAND_*` files. `WarpwoodRodUpdate` is TM `WandHandler`: without warp ward and with permanent warp, every `round(WARP_WAND_REFRESH_BASE / permanent warp)` ticks (at least 1) it adds 1 vis of every primal; it runs on the server only, from the base `WandItem.inventoryTick`.
- Plants (`plants/`): nightshade damage is the damage type `taintedmagic:nightshade` (message `death.attack.taintedmagic.nightshade`, scaling always, exhaustion 0.3 like a 1.7 `DamageSource`). The bush hurts living entities inside it by 1 and poisons them for 140 ticks, drops 1-3 berries or itself to shears. Berries deal 32767 nightshade damage; the funguar gives regeneration II for 60 ticks, speed III for 100 ticks and one random primal aspect to the research pool.

## Generated files (do not edit by hand)

| File | Generator |
|---|---|
| `src/main/resources/assets/taintedmagic` (textures, sounds, lang) | `tools/convert_assets.py` (+ `tools/assets_extra/`, `tools/lang/`) |
| `src/generated/resources` (rewritten completely) | `tools/gen_resources.py` with the features of `tools/features.txt` (`gen_<feature>.py`) |
| `reference/tm-src` | `tools/fetch_tm.py` |
| `tools/tm_research.json`, `tools/tm_recipes.json` | `tools/extract_tm.py` |

- Textures keep the TM folders with `blocks` renamed to `block` and `items` to `item` (`models`, `gui`, `misc`, `foci` stay). A texture named after a TM registration name and meta gets the port id from `id_map.json` with its suffix kept (`ItemMaterial0` is `shadow_metal_ingot`, `BlockWarpwoodLog_side` `warpwood_log_side`, `ItemFocusDarkMatter_depth` `focus_dark_matter_depth`); any other name becomes snake_case (`ModelWAND_CAP_SHADOWMETAL` is `model_wand_cap_shadowmetal`). Block models see only the block atlas: `gen_resources.py` fails on a `taintedmagic` texture outside `block/` and `item/`.
- Lang keys: blocks `block.taintedmagic.<id>`, items `item.taintedmagic.<id>`. Research `tm.name.KEY` becomes `tc.research_name.KEY`, `tm.tag.KEY` `tc.research_text.KEY` (the `[TM] ` prefix is added in code like `TMResearchItem.getText`), `tm.text.KEY.N` `tc.research_page.KEY.N` (TM pages already count from 1 like the base). `itemGroup.TaintedMagic` becomes `itemGroup.taintedmagic`, `death.attack.X` `death.attack.taintedmagic.X` (damage type message ids are namespaced); `tc.research_category.*`, `focus.upgrade.*`, `item.Wand.*` and `item.Focus.*` stay as they are because the base reads them; anything else (`text.*`, `key.*`) gets the `taintedmagic.` prefix.
- TM ships `ru_RU`, `fr_FR`, `ja_JP` and `zh_CN`; they are converted like `en_US`. Manual additions go only to `tools/lang/<lang>.json` and `tools/lang/<feature>/<lang>.json`.
- After a lang change: `convert_assets.py`, then `gen_resources.py`.

## id_map.json

- Edited by hand, same schema as WG: `old` (TM registration name), `meta`, `lang` (en_US.lang key), `id`, `state` (blocks only), `skip`, optional `no_item` and `variant`. Every `tile.*.name`/`item.*.name` key of en_US.lang must be covered, `inventory.py --check` verifies it.
- Ids follow the base names: `shadow_metal_ingot` like `void_metal_ingot`, `<material>_wand_cap`, `warpwood_rod`/`warpwood_staff_core`, `focus_<name>`. A meta meaning another thing gets its own id (`ItemMaterial`, `ItemSalis`, `ItemWandRod`, `ItemWandCap`, the three `ItemKatana` materials). `lumos` and `warpwood_knot` (log meta 2, sharing the log name) are blocks without an item.

## Checks

```sh
python3 tools/fetch_tm.py
python3 tools/convert_assets.py
python3 tools/extract_tm.py && git status --short tools/tm_research.json tools/tm_recipes.json
python3 tools/gen_resources.py && git status --short src/generated
python3 tools/inventory.py --check
python3 tools/check_seams.py
./gradlew build
./gradlew runGameTestServer
```

- Regeneration must not change files.
- `tools/tc4_refs.json` is copied from WG (TC4 meta references to base ids); `tools/tc4_ref.py` rebuilds it only from a base checkout that has `reference/decompiled` and `tools/convert_tags.py`.
